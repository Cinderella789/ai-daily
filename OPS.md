# Эксплуатация на VPS

Пайплайн крутится на личном VPS под пользователем `cinderella`, запускается системным cron.
С 10.05.2026 cron переехал сюда с GitHub Actions: Actions пропускал запуски и задерживал их
на 4-5 часов (в `.github/workflows/update-news.yml` остался только ручной `workflow_dispatch`).

## Где лежат скрипты — и почему в корне

Рабочие скрипты лежат **в корне репозитория**, и cron запускает именно их:

| скрипт | когда | что делает |
|---|---|---|
| `run-update.sh` | 08, 12, 16, 20 МСК | `fetch_feeds → classify_news → translate_news → dedup_news → append_archive → mirror → commit & push → send_telegram` |
| `run-digest.sh` | 09:00 МСК | утренний email-дайджест (`scripts/build_digest.py`), коммитит метку `data/.last-digest-date.txt` |
| `health-watch.sh` | каждый час | сторож пайплайна, см. ниже |
| `notify.sh` | — | отправка алерта в Telegram: `./notify.sh <info\|warn\|critical\|ok> "<текст>"` |

До 21.09.2026 скрипты лежали в `infra/`, а на VPS их копировали руками через `scp`.
Рабочая копия правилась прямо на сервере и за четыре месяца разошлась с `infra/` на 116 строк —
в git лежало не то, что работало. Теперь копии одна.

## Деплой — это просто push

`run-update.sh` первым делом делает `git pull`, поэтому **репозиторий на VPS и есть развёрнутая версия**:
поправили скрипт → закоммитили → запушили → не позже чем через 4 часа применилось само.

> ⚠️ **Правка на сервере без коммита исчезнет.** Перед `git pull` скрипт выполняет
> `git checkout -- .` — откатывает все незакоммиченные изменения в отслеживаемых файлах
> (иначе pull упал бы на конфликте). Правите что-то прямо на VPS — коммитьте сразу.

## Доступ к GitHub

Push идёт по SSH через deploy key с правом записи:
ключ `~/.ssh/github_ai_daily`, хост `github-ai-daily` в `~/.ssh/config`,
remote `github-ai-daily:Cinderella789/ai-daily.git`.
Ключ не истекает — в отличие от токена (PAT), из-за истечения которого push молчал месяц (см. ниже).

## Переменные окружения (`~/ai-daily/.env`, не коммитится)

```
OPENAI_API_KEY=...            OPENAI_MODEL=...          OPENAI_EMBED_MODEL=...
SMTP_HOST=...  SMTP_PORT=...  SMTP_USER=...  SMTP_PASS=...
DIGEST_TO=...  DIGEST_FROM_NAME=AI Daily      TZ=Europe/Moscow
TELEGRAM_DIGEST_BOT_TOKEN=... TELEGRAM_CHANNEL_ID=...   # бот и канал дайджеста
TELEGRAM_BOT_TOKEN=...        TELEGRAM_CHAT_ID=...
NOTIFY_BOT_TOKEN=...          NOTIFY_CHAT_ID=...        # бот алертов для notify.sh
```

Репозиторий **публичный** — токены только в `.env`, никогда в коде скриптов.
Без `NOTIFY_*` скрипт `notify.sh` не молчит: пишет в stderr и возвращает 1.

## Что сторожит `health-watch.sh`

1. **Push.** Нет ни одного лога с успешной отправкой → critical: сколько суток не проходит push,
   сколько коммитов не отправлено, с какой даты не обновляется сайт.
2. **Давность.** Последний успешный прогон старше 6 ч → critical.
3. **Свежий прогон упал**, не дойдя до push → critical с последней строкой лога.
4. **Выход — сам сайт.** Дата свежей новости на Pages сравнивается с локальной:
   отставание > 8 ч → critical, от 48 ч в тексте появляется число суток;
   сайт не отвечает 3 ч подряд → warn.
5. **Дайджест** не отправлялся > 36 ч → warn.

У каждого алерта троттл 12 ч, состояние — в `data/.health/` (в `.gitignore`).
Проверить сторожа, ничего не отправляя: `NOTIFY=echo ./health-watch.sh`;
порог и адрес сайта переопределяются: `SITE_MAX_LAG_H=0`, `SITE_URL=...`.

**Логи:** `logs/update-YYYY-MM-DD_HH-MM.log`, `logs/digest-YYYY-MM-DD.log`, хранятся 30 дней.

## Инциденты

**20-22.05.2026 — сайт стоял 2 дня.** `cache/.embeddings-cache.json` распух до 100+ МБ,
push упёрся в лимит GitHub, 9 коммитов застряли локально.
Починка: `cache/` в `.gitignore` и убран из `git add`; проверка кода выхода `git push`;
логи вместо `> /dev/null` в crontab. Сейчас кэш эмбеддингов ~60 МБ и в git не попадает.

**20.08-21.09.2026 — сайт стоял месяц.** Обнулился `~/.git-credentials` (скорее всего истёк токен,
и git сам стёр запись после отказа) — push падал каждый прогон, 161 коммит застрял локально.
Не заметили, потому что Telegram-канал работал (у него свой токен), а все проверки смотрели
на шаги пайплайна, а не на сайт. При этом ветка «нет успешных прогонов» слала critical каждый час
без троттла — ~28 алертов в сутки, которые приучили их игнорировать.
Починка: SSH deploy key вместо токена; троттлы; проверка выхода (п. 4 выше);
текст алертов называет настоящую причину.
